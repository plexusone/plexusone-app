# v0.7.0

**Release Date:** 2026-10-29

## Highlights

- **Claude names everywhere** - Pane headers and the Claude Sessions window show each session's Claude name, such as `github-com-8b`, and its live status
- **Know when a session needs you** - A notification, a Dock badge, and `⌘J` take you to sessions waiting at a permission prompt or other question
- **Crash recovery in one step** - Restoring saved windows recreates missing tmux sessions by resuming the Claude session that ran in each, and an optional hook remembers tmux names while the app is closed

## What's New

### Claude Names and Live Status

Claude Code names each session, and sessions use these names to address each other, while you know panes by their tmux name. PlexusOne Desktop now shows both:

- Each pane header shows the Claude name after the tmux session name. When the session is waiting for you, an orange badge says what for, such as `waiting: permission prompt`.
- The Claude Sessions window has a **Claude Name** column, shows a running session's live status (`busy`, `idle`, or what it is waiting for) beside its state, and searches by name.
- The app keeps a tmux option, `@claude_name`, on each tmux session, so your tmux status line can show the name too. Add these lines to `~/.tmux.conf`:

```tmux
set -g status-left '[#S]#{?@claude_name,[#{@claude_name}],} '
set -g status-left-length 40
```

### Waiting Sessions

- When a Claude session starts waiting for you, PlexusOne Desktop posts a notification such as *"github-com-8b in tmux acad is waiting: permission prompt"*. Click it to go to that session. Turn notifications off in **Settings > Sessions**.
- The Dock icon shows how many sessions are waiting.
- **Window > Jump to Next Waiting Session** (`⌘J`) cycles through them.
- Going to a session focuses the pane already showing it, in whichever window it is, and opens a window only when no pane shows it. Double-clicking a running session in the Claude Sessions window does the same.

### More in the Claude Sessions Window

- **Last Prompt** and **Cost** columns; the detail pane also shows lines added and removed, from Claude Code's cost record.
- The **Repository** column shows where a session did its work, ranked by how many of the files it read or edited fall in each repository, rather than the directory it started in.
- **Rename Claude Session...** (right-click a running session) types `/rename <name>` into the session's pane. It is available only while the session is idle at its prompt, so it cannot interrupt work.

### Crash Recovery

- **Restore at launch recreates tmux sessions.** When the saved windows expect tmux sessions that no longer exist, each is recreated under the same name by resuming the Claude session that last ran in it. The windows then open with their saved layouts.
- **Optional Claude Code hook.** By itself the app learns a session's tmux name only while it runs. **Settings > Sessions > Install Hook** adds two Claude Code hooks to `~/.claude/settings.json` (backed up first; only the app's own entries are touched). Each Claude session then records its tmux pane at start and on every prompt, even while PlexusOne Desktop is closed. **Remove Hook** takes them out again.

See the [Claude Sessions guide](https://github.com/plexusone/plexusone-app/blob/main/docs/guides/desktop/claude-sessions.md).

## What's Changed

- Only one copy of PlexusOne Desktop runs at a time. Opening a second copy brings the running one forward, so two copies never write the same state files.
- When Claude Code's live record lacks a tmux location, the app finds the session's pane from the process tree.

## What's Fixed

- TUI Parser handles errors from HTTP writes, PTY and server closes, detaching, and sending keys instead of ignoring them.

## Documentation

- The Claude Sessions guide covers Claude names, the tmux status line, waiting alerts, renaming, the hook, and crash recovery
- [ADR 0003](https://github.com/plexusone/plexusone-app/blob/main/docs/design/adrs/0003-claude-code-hook-recording.md): recording sessions with a Claude Code hook

## Upgrading

Quit the running PlexusOne Desktop before opening the new version. With only one copy allowed to run, opening v0.7.0 while v0.6.0 is running brings v0.6.0 forward instead.

## Install

Open the `.dmg` and drag PlexusOne Desktop to Applications. Builds are ad-hoc signed but not notarized: on first launch, open **System Settings > Privacy & Security** and click **Open Anyway**.
