# v0.6.0

**Release Date:** 2026-10-27

## Highlights

- **Claude Sessions window** - See every Claude Code session with its tmux session, subject, repositories, last activity, and how it ended, and bring back the ones you want after a crash or restart
- **Trackpad scrolls the conversation** - Scrolling now moves back through a session's history instead of stepping through Claude Code's past prompts
- **Menus and multiple windows work** - New Session, Attach, Detach, and Next/Previous Pane act on the front window, and restoring several saved windows no longer hangs

## What's New

### Claude Sessions Window

Open it with **File > Claude Sessions...** (`⇧⌘S`) or the list button in a window's toolbar.

Each Claude Code session shows its tmux session, its subject (Claude's title, else the first prompt), the git repositories it worked in as `github.com/org/repo`, when it was last active, and its session ID. Select a session for its full details: directory, branch, first and last prompts, every repository it read or edited, and the command that resumes it. Filter by how recently a session was active, by state, or by search.

The window also shows how each session ended:

| State | Meaning |
|-------|---------|
| Running | Claude Code is running |
| Exited normally | Claude exited while its tmux pane stayed open, for example with `/exit` or Ctrl+C |
| tmux/terminal closed | The tmux pane, session, or server closed while Claude was running in it |
| System shutdown | Claude was still running when the machine shut down, restarted, or crashed |
| Crashed/killed | The Claude process died without cleaning up |
| Ended cleanly | Claude shut down cleanly while PlexusOne Desktop was not running |
| Ended abnormally | No clean shutdown was recorded and the machine has not restarted since |

Claude Code's own files show whether it shut down cleanly, but a closed terminal looks the same as `/exit` there. PlexusOne Desktop tells them apart by watching while it runs, and it remembers each session's tmux name in `~/.plexusone/claude-sessions.json`.

**Restoring sessions:** double-click a session, or select several and choose Resume. For each session you choose the tmux session name; the remembered name is filled in when there is one. PlexusOne types `claude --resume <id>` into a new shell in the session's directory, in a new window of that tmux session if it still exists, or in a new tmux session. The restored sessions open together in one window. After a crash, a banner offers to restore every session that ended abnormally in the last 48 hours.

See the [Claude Sessions guide](https://github.com/plexusone/plexusone-app/blob/main/docs/guides/desktop/claude-sessions.md).

### Keyboard Commands

| Shortcut | Action |
|----------|--------|
| `⇧⌘S` | Claude Sessions window |
| `⌥⌘A` | Attach a session to the focused pane |
| `⇧⌘A` | Detach the focused pane |
| `⌘]` / `⌘[` | Next / previous pane |

Attach moved from `⌘A`, which is Select All again.

## What's Fixed

### Trackpad Scrolling

With tmux mouse mode off, tmux keeps the terminal on its alternate screen, where scrolling is sent as Up/Down keys. In Claude Code those keys step through past prompts, so the trackpad could not scroll back through a conversation. Attaching a pane now turns on tmux mouse mode for that tmux session only, so scrolling moves through its history. Up/Down still navigate prompt history, and holding Shift while dragging selects text as before. Your `~/.tmux.conf` is not changed; to keep your own tmux mouse setting, turn off **Settings > Sessions > Trackpad scrolls conversation history**.

### Windows and Menus

- Restoring two or more saved windows hung the app; each additional window now opens with its saved layout
- New Window and Pop Out opened one window for every window already open
- New Session, Attach, Detach, and Next/Previous Pane did nothing; they now act on the front window

### Panes

- Pane headers and the status bar show each session's current status instead of its status when the pane was attached
- The input-needed badge clears once the prompt is answered, and notifications fire once when a prompt appears rather than on every redraw
- Scrolling works on an unfocused pane, and typing scrolls a pane back to its latest output
- Switching or detaching a pane no longer leaves a zombie tmux process

### Sessions

- Session list updates run on the main thread, and tmux commands no longer block threads Swift's concurrency runtime depends on
- tmux session names containing `|` are listed correctly, and blank names are rejected
